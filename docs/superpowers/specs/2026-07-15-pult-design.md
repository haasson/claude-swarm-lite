# Пульт — единое окно ответов агентам

Дата: 2026-07-15

## Цель

Когда несколько агентов работают одновременно, они зовут по очереди, и время
уходит на **охоту**: какая из вкладок меня звала. Пульт убирает охоту. Это
закреплённая вкладка, где сверху лежит очередь всех, кто ждёт ответа, а снизу —
живой терминал выбранного из очереди. Ответил — очередь сама показала
следующего.

Пульт не заменяет дашборд и не показывает тех, кто работает: пустой пульт
означает «никто не зовёт, можно заниматься своим».

## Ключевое решение: пульт не показывает копию терминала

Все терминалы уже лежат в одном `#stage`, видимость переключается классом
`.active` на холдере (`renderer.js:1053`). Поэтому «показать в пульте терминал
агента» — это сделать активным его холдер. Второго xterm, переноса DOM-нод и
копирования pty-потока не нужно.

**Пульт — это `#stage` плюс полоска над ним.**

Отсюда следствие, определяющее весь остальной дизайн: терминал внизу
**настоящий**, поэтому отвечают в него обычным набором с клавиатуры — так же,
как во вкладке агента. Ни кнопок с вариантами, ни отдельного инпута, ни
`sendInput('2\r')`, ни парсинга тела вопроса в спеке нет. Это осознанно
отброшенная сложность, а не пропуск.

## UI

```
┌─ Вкладки ──┬──────────────────────────────────────────┐
│ ◆ Пульт  ⌘1│  ждут: ⟨● Меню · 0:12⟩ ⟨● Тесты · 1:40⟩  │  ← #pult-strip
│ ● Меню     ├──────────────────────────────────────────┤
│ ● Диффы    │                                          │
│ ○ Тесты    │   ● Какой цвет иконки?                   │
│            │                                          │  ← #stage:
│            │   ❯ 1. Синий                             │    настоящий холдер
│            │     2. Серый                             │    вкладки «Меню»
│            │                                          │
│            │   > _                                    │
└────────────┴──────────────────────────────────────────┘
```

### Вкладка «Пульт»

- Закреплена первой в `#tabs`, **выше всех групп по папкам**, вне их. Не
  относится ни к одной папке, не участвует в drag & drop, не имеет кнопки `×`.
- Единственная вкладка без pty. В `sessions` не попадает — это статический
  элемент, который `relayoutTabs()` (`renderer.js:1151`) добавляет в начало
  `#tabs` при каждой перестройке.
- Значок-счётчик справа от названия: сколько агентов в очереди. Ноль — счётчик
  скрыт.
- Не сохраняется в `persistTabs` — сохранять нечего, вкладка есть всегда.

### Полоска очереди `#pult-strip`

- Новая строка в CSS-grid `body` над `#stage`; спанит колонку `#stage` в обеих
  раскладках (`.layout-rail` и `.layout-top`). Видна только в режиме пульта.
- Содержит чип на каждого агента в очереди. Чип: цветная точка статуса + имя
  вкладки + время ожидания (`м:сс`) + короткая строка вопроса (см. ниже).
- Чип выбранного агента подсвечен — его терминал показан ниже.
- Клик по чипу → показать терминал этого агента, не выходя из пульта.
- Очередь пуста → вместо полоски и терминала показывается `#pult-empty`:
  «Никто не ждёт ответа». Все холдеры скрыты.

### Порядок очереди

По времени начала ожидания, дольше всех ждущий — первым. Порядок вкладок и папок
на очередь не влияет: очередь про «кто дольше простаивает», а не про раскладку.

## Поведение

### Вход и выход

- ⌘1 или клик по вкладке «Пульт» → режим пульта. Выбирается голова очереди; если
  ранее выбранный агент всё ещё ждёт — остаётся он.
- Клик по вкладке любого агента в рейле или ⌘2–⌘9 → режим пульта выключается,
  обычный вид вкладки.

**Хоткеи агентов сдвигаются:** ⌘1 занимает Пульт, агенты переезжают на ⌘2–⌘9
(`renderer.js:1770`, индекс в `sessions` теперь `Number(e.key) - 2`). Это
сознательная ломка мышечной памяти в обмен на то, что пульт — самое частое
место, куда возвращаешься.

### Ответ и продвижение очереди

Фокус при выборе чипа уходит в терминал (`activate()` это уже делает,
`renderer.js:1067`), поэтому набранное идёт прямо в pty агента.

После ответа агент выходит из `waiting`, его чип пропадает, пульт автоматически
показывает следующего в очереди. Пустая очередь → `#pult-empty`.

Перехода не будет резким: `onStatus` буферизует покраску `running` на
`RUN_BUFFER_MS = 2500` (`renderer.js:278`), так что чип живёт ещё ~2.5 с после
ответа. Это желаемое поведение, а не побочный эффект — успеваешь увидеть, что
агент принял ответ.

### Что режим пульта НЕ меняет

- **Уведомления.** `maybeNotify` (`renderer.js:1341`) работает как сейчас и
  ведёт во вкладку агента, не в пульт.
- **Git-бар.** Показывает ветку выбранного агента — `activeId` указывает на
  него, `refreshGit()` уже вызывается из `activate()`.
- **⌘W.** В режиме пульта не делает ничего. Сейчас он закрыл бы `activeId`,
  то есть чужого агента, которого ты просто смотришь, — это неожиданно. Пульт
  тоже не закрывается: вкладка постоянная.

## Состояние в рендерере

- `pultOn: boolean` — режим пульта. Отражается классом `pult-on` на `body`.
- `activate(id, { pult })` — существующая функция получает флаг. Без флага
  (клик по вкладке агента) режим выключается; с флагом (клик по чипу) остаётся.
- `s.waitingSince: number | null` — момент входа в `waiting`. Ставится в
  `setStatus` (`renderer.js:256`) по образцу `runningSince` (`renderer.js:287`),
  сбрасывается при любом другом статусе. Источник таймера и порядка очереди.
- `s.question: string | null` — строка вопроса из `session:status`.
- `renderPult()` — перерисовка полоски. Вызывается из `onStatus` при изменениях
  и раз в секунду по таймеру, пока `pultOn` (только ради тикающих таймеров;
  вне режима таймер не крутится).

## main-процесс: строка вопроса в чипе

Единственное место, где нужен разбор экрана. Он нужен для триажа: увидеть, что
«Тесты» просят `rm -rf build`, а «Меню» спрашивает про цвет иконки, — не кликая
по каждому чипу.

`snapshot(d)` (`main.js:156`) уже снимает нижние `SNAP_ROWS = 16` строк экрана
каждый тик, и `decide()` (`main.js:197`) уже знает момент, когда вопрос на
экране. Добавляем в `session:status` (`main.js:236`) поле `question: string |
null` — рядом с `detail` и `statusline`. Канал дифференциальный, preload и
подписка в рендерере уже есть; новых IPC-каналов не нужно.

### Новый модуль `screen.js`

Чистая функция в отдельном модуле — по образцу `git.js` и `updater-core.js`,
чтобы тестировать без Electron.

`extractQuestion(snapshot) → string | null` — ищет снизу вверх первую строку,
которая:

- не пустая;
- не строка варианта — `/^\s*[❯>→➜▸►▶]?\s*\d+\.\s/`;
- не рамка — `/^[\s│┌└├─╭╰╮╯]*$/`;
- не подсказка — `/Esc to cancel|Enter to confirm/i`.

Найденную строку чистим: срезаем рамки `│` по краям, схлопываем пробелы,
обрезаем до 80 символов. Ничего не нашли — `null`.

Вычисляется только когда `decide()` вернул `waiting`; в остальных статусах поле
`null`.

### Деградация

Парсинг экрана хрупок к смене TUI Claude Code — ровно так же, как нынешний
детектор статуса (`RE_WAIT`, `main.js:123`, где набор глифов курсора уже
приходилось расширять). Но ломается он мягко и в одном месте: `question ===
null` → чип показывает имя вкладки и таймер, очередь и терминал работают
полностью. Ни один сценарий не блокируется.

Очередь и полоска — DOM-логика в `renderer.js`, тестов не имеет, как и
остальной рендерер.

## Что сюда не входит

- Кнопки вариантов и инпут в карточке — не нужны, терминал настоящий.
- Показ работающих/готовых агентов в пульте — для этого есть рейл и дашборд.
- Изменение поведения уведомлений.
- Отдельное окно пульта.
