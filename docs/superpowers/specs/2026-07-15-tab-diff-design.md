# Дифф вкладки (в стиле GitLab MR)

Дата: 2026-07-15

## Цель

Показывать в нижнем статус-баре, рядом с веткой, счётчик изменений рабочей папки
**активной** вкладки (`+1203 −300`) и по клику открывать просмотр этих
изменений: дерево тронутых файлов слева, красно-зелёный unified diff справа —
как merge request в GitLab.

Задача, которую это решает: агент пишет код, и понять «сколько он наработал»
сейчас можно только уйдя в терминал и набрав `git diff` руками. Счётчик отвечает
на это одним взглядом, оверлей — одним кликом.

Счётчик живёт там же, где ветка, и по той же логике: статус-бар отражает
активную вкладку (`renderer.js:556`). Осознанный размен — по остальным вкладкам
изменений не видно, для картины по всем агентам придётся перещёлкивать. Взамен
дизайн остаётся ровно в габаритах существующего git-бара: тот же `refreshGit`,
тот же таймер, никакого опроса N папок.

По ощущению — как дифф в Warp, но read-only и без встроенного редактора
(см. «Чего не делаем»).

## Скоуп диффа

Считаем и показываем **незакоммиченную работу**: `git diff HEAD` плюс новые
(untracked) файлы.

Почему именно это: агент коммитит сам, и счётчик, обнуляющийся после коммита,
честно отвечает на вопрос «что сейчас не сохранено». Дифф всей ветки против
`main` требует знать базовую ветку (её нет), а дифф «от начала сессии» ломается
на первом же `checkout`.

Untracked входят в счёт обязательно: Claude постоянно создаёт новые файлы, а
`git diff HEAD` их не видит — новый файл на 200 строк дал бы `+0`. GitLab
показывает новые файлы в MR, и мы показываем.

## Чего не делаем (YAGNI)

**Редактирование файлов.** В Warp файлы правит человек, а агент работает по его
команде — пишет кто-то один. Здесь swarm: несколько агентов правят файлы прямо
сейчас, само наличие опроса раз в 2.5 с — следствие того, что содержимое
меняется само. Редактор в такой среде — гонка на запись: открыл файл, начал
печатать, Claude переписал его целиком, «сохранить» молча снесло его работу.
Чтобы это не стреляло, нужны mtime-guard, детект внешнего изменения, диалог
«файл изменился», undo — половина IDE, и вся про конфликты. Вместо этого —
кнопка «открыть в редакторе» (`shell.openPath`), которая отдаёт файл в уже
открытую на этом проекте IDE.

**Откат файла/ханка** (`git checkout -- <file>`, `git apply --reverse`).
Органичный жест при просмотре агентского диффа, ложится на существующий
`runGit`. Но операция разрушительная, а агент может писать в тот же файл в этот
момент. Отдельный спек, если понадобится.

**Дерево всего проекта.** Файловый браузер с чтением директорий, `.gitignore` и
ленивой подгрузкой — отдельная фича со своим IPC, к диффу отношения не имеющая.
Здесь дерево строится только из путей, которые уже вернул `--numstat`.

**Свой keybind на оверлей.** Открытие — кликом по счётчику, закрытие — Esc.
Правка `keybinds.js` — отдельная история.

## Архитектура

Три юнита, каждый по уже принятому в репозитории паттерну.

### `git.js` (+~60 строк)

Две новые чистые функции рядом с существующими:

- `gitDiffStat(cwd)` → `{ added, removed, files: [{ path, added, removed,
  status }] }`, где `status` ∈ `modified | added | deleted | renamed | binary`.
  Для переименования `path` — новый путь, старый в `oldPath`.
- `gitDiffText(cwd, path)` → unified diff **одного** файла строкой.

Дифф грузится **лениво, по файлу**. `+1203 −300` может весить мегабайт; гнать
его целиком через IPC ради показа первого файла незачем.

Шапка модуля сейчас обещает «child_process only» — правится: добавляется `fs`
(см. ниже). «Без Electron» остаётся в силе, модуль по-прежнему требуется из
голого `node`.

### `renderer/diffview.js` (новый, `window.SWARM_DIFF`)

Чистые функции, без DOM:

- `parseUnified(text)` → `[{ header, lines: [{ type, text, oldNo, newNo }] }]`,
  где `type` ∈ `add | del | ctx | meta`.
- `buildTree(files)` → вложенная структура папок из плоского списка путей.

Подключается скриптом до `renderer.js` и требуется из тестов — ровно как
`themes.js`, `keybinds.js`, `resume.js`, `logstore.js`.

### `renderer.js`

Только проводка: счётчик в статус-баре, разметка оверлея, обработчики.
Файл уже 2022 строки, поэтому вся логика живёт в `diffview.js`, здесь остаётся
вёрстка.

### IPC

`main.js` + `preload.js` получают по копии существующих строк:

- `git:diffstat(cwd)` → `DiffStat`
- `git:difftext(cwd, path)` → `string`

## Поток данных

**Никаких новых таймеров.** Счётчик нужен только для активной папки, а её уже
опрашивает `refreshGit` каждые 2.5 с. `git:diffstat` вызывается там же, рядом с
`git:info`, и рисуется тем же `renderGitBar`. Как и `refreshGit`, вызов
сверяет `activeId` перед отрисовкой — иначе ответ по старой папке перезапишет
бар после переключения вкладки.

Если вызов для папки ещё в полёте, следующий тик его пропускает: на большом
репозитории `--numstat` может не уложиться в 2.5 с, и без этого тики копят
очередь.

**Untracked без спавна git.** `git status --porcelain -uall -z` даёт список
новых файлов, но не их размер в строках, а `git diff --no-index` пришлось бы
звать по файлу отдельно: агент создал 50 файлов — 50 процессов каждые 2.5 с.
Вместо этого `git.js` читает новые файлы через `fs` и считает строки сам, с
кешем по `mtime + size`: в устоявшемся состоянии это `stat()` на файл, а не
чтение.

- NUL-байт в первых 8 КБ → файл бинарный, показывается как `BIN`, в счётчик не
  идёт.
- Больше 2 МБ → пропускается с пометкой, а не врёт нулём.

Побочный плюс: дифф нового файла тоже синтезируется в JS (все строки — `+`),
поэтому `--no-index` с его `/dev/null` не нужен вообще — а он на Windows
отдельная головная боль. Меньше кода и меньше платформенных сюрпризов.

**Оверлей — снимок, а не живой поток.** Пока читаешь дифф, агент пишет в те же
файлы; перерисовка под курсором увела бы текст посреди чтения. Оверлей
фиксирует состояние на момент открытия. Когда счётчик разошёлся с показанным, в
шапке всплывает неброское «изменилось — обновить» — перечитывает пользователь,
кликом.

## UI

### Счётчик в статус-баре

Новая кнопка `#git-diff` в `#statusbar`, сразу за `#git-branch`:

```
 ⎇ main ↓1   +120 −30              ⚙ ☰ ⇄
             └── клик → оверлей
```

- `+N −M`: `+N` зелёным, `−M` красным.
- Папка не git-репозиторий или изменений нет → кнопка скрыта, как и
  `#git-branch` (`hidden`, тот же молчаливый паттерн).
- Клик → оверлей. Это `<button>`, а не текст: курсор, фокус и клавиатура
  достаются бесплатно.

**Маркер `*` из ветки убирается.** Сейчас `renderGitBar` рисует `*` при
`info.dirty` (`renderer.js:567`) — «есть незакоммиченное». Рядом с `+120 −30` он
говорит то же самое, только хуже. Счётчик его вытесняет.

Само поле `gitInfo.dirty` остаётся: оно часть формы `gitInfo`,
задокументированной в шапке `git.js`, а `git.js` — самостоятельный модуль,
пригодный для вызова из голого `node`, а не приватная деталь бара. Убираем
только строку отрисовки (`renderer.js:567`).

Проверить при реализации: `dirty` считается через `git status --porcelain` в
`gitInfo`, а `gitDiffStat` зовёт `status --porcelain -uall -z` ради untracked.
Это два почти одинаковых вызова на каждый тик. Если так — свести к одному,
вернув `dirty` из общего разбора.

### Оверлей

Переиспользует существующий `.modal-overlay` (логи, настройки). Терминал под ним
цел — размеры xterm не трогаются, refit не нужен, ломать нечего.

```
┌───────────────────────────────────────┐
│ Изменения — proj-a       +120 −30   ✕ │
├──────────────────┬────────────────────┤
│ ▾ renderer/      │ @@ -10,7 +10,9 @@  │
│    renderer.js   │   const x = 1;     │
│      +80 −12     │ − old line         │
│    diffview.js   │ + new line         │
│      NEW +120    │   const y = 2;     │
│ ▾ test/          │                    │
│    diff.test.js  │                    │
│   git.js  +40 −8 │                    │
└──────────────────┴────────────────────┘
```

- Слева — дерево тронутых файлов с счётчиком и статусом у каждого.
- Справа — unified diff выбранного файла: `.add` зелёным фоном, `.del` красным,
  `.ctx` нейтральным, `@@`-заголовки ханков — приглушённо.
- Номера старой и новой строки в двух колонках слева от текста.
- На файле — кнопка «открыть в редакторе» (`shell.openPath`).
- Esc и `✕` закрывают.

Цвета берутся из существующих переменных `:root` в `styles.css`, а не задаются
новыми константами: `--ready` (`#4ade80`) для добавленного, `--danger`
(`#e05a5a`) для удалённого, `--panel`/`--border`/`--muted` для обвязки. Фон
строк — через `color-mix(in srgb, var(--ready) 14%, transparent)`, как уже
делают `.modal-ok:hover` и `.git-branch:hover`.

Важно: `themes.js` тут **ни при чём** — это пресеты xterm (`ITheme` + 16 ANSI),
они красят терминал, а не хром. У хрома одна фиксированная палитра в `:root`,
светлой темы нет. Дифф — часть хрома.

## Границы и ошибки

Главный риск — **не производительность git, а DOM**. Файл с 50 000 изменённых
строк — это 50 000 узлов, и оверлей встанет колом. Рендер файла обрезается на
2000 строках с честной плашкой «показаны первые 2000 из N — открыть в
редакторе». Обрезается **показ, но не счётчик**: `+1203` считается по
`--numstat` и не зависит от того, сколько мы нарисовали.

Дальше — случаи, где git отдаёт не то, что ждёт наивный парсер:

- **Репозиторий без коммитов.** `git diff HEAD` падает — HEAD не существует.
  Диффим против пустого дерева
  (`4b825dc642cb6eb9a060e54bf8d69288fbee4904`), тогда первый коммит проекта
  показывается нормально, а не ошибкой.
- **Пути с пробелами и кириллицей.** `--numstat` по умолчанию квотит такие пути
  (`"\320\272..."`), и наивный `split('\t')` их искалечит. Везде `-z`:
  NUL-разделители, никакого квотинга. Интерфейс русский, файлы с русскими
  именами — вопрос времени.
- **Переименования.** В `-z` формате приходят особой формой: после счётчиков
  идут два NUL-терминированных пути (старый, затем новый), а не `old => new`
  одной записью. Парсится явно, показывается как `RENAMED`.
- **Бинарные файлы.** `--numstat` отдаёт `-`/`-` вместо чисел. `Number('-')` —
  это `NaN`, и счётчик в баре станет `+NaN`. Ловим, показываем `BIN`.
- **`\ No newline at end of file`.** Реальный маркер unified diff; парсер обязан
  его знать, иначе примет за строку контекста.
- **Удалённая папка, отсутствие git, таймаут.** Уже покрыто: `runGit` не
  бросает, возвращает `code != 0` → папка просто без счётчика.
- **Вкладка закрыта при открытом оверлее** → оверлей закрывается.

## Тесты

`test/diff.test.js`, следующей строкой в `npm test`. Плоский `node` + `assert`,
без фреймворка — как `logstore.test.js` и `resume.test.js`.

Парсер (`parseUnified`):
- один ханк, несколько ханков в файле;
- `\ No newline at end of file`;
- CRLF;
- пустой дифф;
- полностью удалённый файл;
- корректная нумерация старых/новых строк.

Разбор `--numstat -z`:
- переименование (два пути);
- бинарник — `-`/`-` не даёт `NaN`;
- юникодный путь и путь с пробелом;
- пустой вывод.

Дерево (`buildTree`):
- группировка плоского списка в вложенные папки;
- файл в корне рядом с вложенными;
- одиночный файл.

Всё это — чистые функции над строками, поэтому тесты обходятся без git и без
временных репозиториев: фикстуры — просто текст.

## Риски

- **Размер `renderer.js`.** Файл уже великоват; вёрстка оверлея добавит строк.
  Если разрастётся сверх ожидаемого — вынести разметку оверлея в отдельный
  модуль тем же паттерном, что `diffview.js`.
- **Стоимость опроса на большом монорепозитории.** `git diff HEAD --numstat` на
  очень крупном дереве может не уложиться в 2.5 с. Защита от очереди
  (in-flight guard) есть; если окажется мало — считать счётчик на своём, более
  редком таймере, отдельно от ветки. Проверяется на реальном репозитории при
  реализации.
- **Видно только активную вкладку.** Принятый размен (см. «Цель»): по остальным
  агентам изменений не видно без переключения. Если это начнёт мешать —
  расширяется дёшево: `gitDiffStat` уже принимает произвольный `cwd`, так что
  нужен только батчевый IPC на список папок и место под цифры в рельсе.
  Существенная деталь на будущее: дифф — свойство **папки**, а не вкладки, а
  вкладки группируются по папке (`renderer.js:1148`). Значит счётчик пойдёт на
  заголовок группы и на карточку одиночной вкладки; повесить его на каждую
  карточку в группе нельзя — два агента в одном проекте показали бы одни и те же
  `+120` дважды, будто наработали по отдельности.
