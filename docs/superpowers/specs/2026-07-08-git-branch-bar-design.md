# Git-бар снизу (в стиле VS Code)

Дата: 2026-07-08

## Цель

Показывать git-ветку рабочей папки **активной** вкладки в нижнем статус-баре и
дать быстрые действия по клику: переключение ветки, обновление (fetch/pull),
индикатор «есть что подтянуть». По ощущению — как git-статусбар в VS Code, но
без лишнего: без графа, без создания веток, без UI-логина.

## UI

### Статус-бар `#statusbar`
- Новый элемент на всю ширину окна, тонкий (~24px), снизу — под `#chrome` и
  `#stage`.
- В CSS-grid `body` добавляется нижняя строка `auto`; бар спанит все колонки в
  обеих раскладках (`.layout-rail` и `.layout-top`).
- Слева — блок ветки: иконка ветки + имя текущей ветки активной сессии, затем
  индикаторы:
  - `↓N` — можно подтянуть N коммитов с remote (behind).
  - `↑N` — локально впереди на N коммитов (ahead).
  - `*` — есть незакоммиченные изменения (dirty).
- Если папка активной сессии **не** git-репозиторий — блок ветки скрыт, бар
  пустой/минимальный.
- Клик по блоку ветки → всплывающее меню над баром (переиспользуем визуальный
  стиль существующего `#cmd-menu`).

### Меню (по клику)
- Заголовок: текущая ветка + ahead/behind.
- **Обновить** → `git fetch`, после — пересчёт `↓/↑`.
- **Подтянуть (git pull)** — пункт показывается, только если `behind > 0`.
- Разделитель.
- **Список локальных веток** (текущая помечена). Клик = `git checkout <branch>`.
- Ошибки действий (например, checkout не прошёл из-за незакоммиченных изменений,
  или fetch/pull упал на аутентификации) показываем короткой плашкой в
  баре/меню. Для auth-ошибки текст: «нужен логин — выполните git fetch/pull в
  терминале».

## main-процесс — git через `child_process`

Все команды выполняются `execFile('git', [...], { cwd, env })` — без shell,
без инъекций. В `env` добавляем `GIT_TERMINAL_PROMPT=0` (и `GIT_ASKPASS` на
пустышку/`echo`), чтобы git **никогда не висел** в ожидании интерактивного
ввода, а сразу падал с ошибкой, которую мы ловим.

Процесс наследует обычную среду (`process.env`) — тот же пользователь,
credential-helper (Keychain), SSH-ключи/ssh-agent — поэтому доступ к remote у
него такой же, как у git в терминале. Отдельный UI-логин НЕ делаем.

Новые IPC-хендлеры (`ipcMain.handle`):
- `git:info(cwd)` → `{ isRepo, branch, ahead, behind, dirty }`.
  - `isRepo`: `git rev-parse --is-inside-work-tree`.
  - `branch`: `git rev-parse --abbrev-ref HEAD` (detached → показываем короткий
    хеш).
  - `dirty`: непусто ли `git status --porcelain`.
  - `ahead`/`behind`: `git rev-list --left-right --count @{upstream}...HEAD`
    (если upstream нет — оба 0, без ошибки).
- `git:branches(cwd)` → `string[]` локальных веток
  (`git for-each-ref --format=%(refname:short) refs/heads`).
- `git:fetch(cwd)` → `{ ok, error? }`, затем возвращает свежий `git:info`.
- `git:pull(cwd)` → `{ ok, error? }` + свежий `git:info`.
- `git:checkout(cwd, branch)` → `{ ok, error? }` + свежий `git:info`.

Все команды с sane-таймаутом (например, 20s для сетевых fetch/pull, короче для
локальных), чтобы подвисшая операция не копилась.

### preload.js
Экспорт под `window.swarm.git`:
```js
git: {
  info:     (cwd)         => ipcRenderer.invoke('git:info', cwd),
  branches: (cwd)         => ipcRenderer.invoke('git:branches', cwd),
  fetch:    (cwd)         => ipcRenderer.invoke('git:fetch', cwd),
  pull:     (cwd)         => ipcRenderer.invoke('git:pull', cwd),
  checkout: (cwd, branch) => ipcRenderer.invoke('git:checkout', cwd, branch),
}
```

## Живое обновление

- Бар отражает папку **активной** вкладки. При переключении вкладок (`activate`)
  — перезапрос `git:info` для новой папки.
- **Лёгкий поллинг** `git:info` активной папки раз в ~2.5s (локально, дёшево),
  чтобы ловить смену ветки / появление изменений, которые `claude` делает прямо
  в терминале — «живой» git, как в VS Code. Поллинг только для активной папки,
  не для всех.
- **Авто-fetch** активной папки раз в ~3 минуты (сетевая операция, отдельный
  таймер, с `GIT_TERMINAL_PROMPT=0`). Обновляет индикатор `↓N` сам, без действий
  пользователя. При auth-ошибке — тихо игнорируем/плашка, не спамим.
- Ручное «Обновить» в меню дёргает `git:fetch` немедленно.

## Обработка ошибок и крайние случаи

- Папки по умолчанию (`~/ClaudeSwarm`) обычно не git-репо → бар просто скрывает
  git-блок.
- Несколько сессий в одной папке делят рабочее дерево: checkout/pull влияет на
  все — это природа git, отдельно не изолируем (без worktrees). Бар отражает
  папку активной вкладки.
- git не установлен / команда упала → трактуем как «не репо» (git-блок скрыт),
  ошибку не навязываем.
- checkout при незакоммиченных изменениях падает → показываем плашку с текстом
  ошибки git, ветку не меняем.

## Что НЕ делаем (YAGNI)

- Создание новых веток.
- Checkout удалённых веток (origin/*) — только показываем, что есть что
  подтянуть.
- UI-окно логина/ввода пароля.
- git-граф, история коммитов, stash, merge/rebase из UI.
