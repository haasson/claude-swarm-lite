# Надёжный статус (хуки + экран) + разрешение/вопрос — Implementation Plan

**Goal:** Сделать статус агентов надёжным и различать **разрешение** и **вопрос**.
Гибрид: **хуки Claude Code — точный фундамент**, снимок экрана — fallback и
дополнение для текстовых вопросов. Это суженная замена фазы A из
`2026-07-15-cmux-adopt.md`: кольцо холдера и ⌘⇧U **выкинуты** как дубль Пульта.

**Что НЕ делаем:** кольцо холдера, ⌘⇧U jump, метаданные вкладок (фаза B),
блокирующие Allow/Deny поверх Claude. Ответ всегда в настоящий терминал.

**Требование:** Claude Code v2.1.141+ (поле `terminalSequence` в выводе хука). У
пользователя 2.1.218 — ок.

---

## Почему гибрид

Сейчас статус — чистое угадывание по снимку экрана (`decide()` в `main.js:260`,
тик 300 мс). Отсюда мигания на перерисовках и потеря текстового вопроса, когда
маркер уезжает из нижних 16 строк снимка.

Хуки Claude Code дают детерминированные сигналы (подтверждено по докам,
Claude Code v2.1.218):

| Хук | Когда | Статус |
|---|---|---|
| `UserPromptSubmit` | юзер отправил промпт | `running` |
| `Stop` | агент закончил ход | `ready` |
| `PermissionRequest` (matcher=tool) | всплыл запрос разрешения | `waiting` + kind `permission` |
| `PreToolUse` matcher `AskUserQuestion` | агент задал структурный вопрос | `waiting` + kind `question` |
| `PostToolUse` / следующий `PreToolUse` | разрешение выполнено | снятие `waiting` |

**Доставка без сокетов/файлов.** Хук возвращает JSON с полем `terminalSequence`
— Claude Code печатает эту OSC-последовательность в pty сессии. Мы парсим её из
сырого чанка (`feedDetector`, `main.js:248`). Т.к. у каждого агента свой pty,
**маршрутизация бесплатна** — знаем, из какого таба пришла метка. `session_id`
тоже есть в payload хука (кладём в метку для страховки).

**Дырка хуков (её латает экран):** агент договорил и задал вопрос **прозой** (не
через AskUserQuestion). Для Claude это обычный конец хода → прилетит `Stop` →
`ready`. Экранный маркер `Сейчас от тебя` (`RE_WAIT_ASK`, `main.js:204`) поднимает
такой `ready` до `waiting`+`question`.

---

## Арбитраж (кто главнее)

**Правило: хук всегда бьёт экран. Экран может только дополнить то, чего хук не
видит, и никогда не переопределяет хук.**

Поля детектора на источник:
- `hookState: { status, kind, at }` — последнее от хуков (авторитет).
- `hooksActive: boolean` — видели ли мы хоть одну метку из этого pty.

Разрешение конфликта на каждом обновлении:

1. Если `hooksActive`:
   - Статус = `hookState.status`. Экран **не может** сделать `running`→`ready` или
     погасить `permission` (это лечит ложные мигания).
   - Единственное право экрана: если `hookState.status === 'ready'` И экран видит
     `RE_WAIT_ASK` → апгрейд до `waiting` + kind `question`.
2. Если не `hooksActive` (fallback): работает старый `decide` + **замок «ждёт»**
   (ниже).

`hooksActive` включается при первой распознанной метке из pty; можно сбрасывать
на `SessionStart`/resume если понадобится (YAGNI пока).

---

## Частота опроса экрана

- `hooksActive && status === 'running'` → экран **не опрашиваем** (хук скажет `Stop`).
- Пришёл `Stop` → короткое окно **быстрых** проверок экрана (напр. 5 тиков по
  300 мс) чтобы поймать прозаичный вопрос; затем — редкий тик (напр. 2 с) или пауза.
- `waiting` (любой kind) → экран не нужен, релиз придёт хуком.
- `!hooksActive` → полный тик 300 мс + замок.

Реализация: тик остаётся, но для сессии с `hooksActive` большинство тиков —
ранний `continue`, кроме окна после `Stop`.

---

## Замок «ждёт» (fallback, без хуков)

Для сессий без хуков — память, чтобы не мигать и не терять вопрос.

Поля: `waitLatched`, `waitLatchedAt`, `waitKind`.

- **Защёлкивание:** классификация дала `waiting` → латчим статус и kind.
- **Пока защёлкнуто — не верим `running`/`ready` с экрана.**
- **Релиз — только когда агент реально возобновил работу** (НЕ по нажатию клавиш;
  печать в поле ответа замок не открывает):
  - **chrome-запрос** (permission/варианты): исчез с экрана prompt-box → релиз
    (prompt-box исчезает только когда запрос закрыт).
  - **прозаичный вопрос**: маркер может уехать из снимка без ответа, поэтому
    держим, пока не увидим реальную работу — `chromeGone && RE_RUNNING.test(snap)`,
    либо `chromeGone` + устойчивый тихий `ready` (страховка от зависания).
- **Kind только усиливаем:** `question → permission` можно, обратно нет.

> Важно: релиз завязан на «агент работает», а не «юзер печатает». Пользователь
> уточнил это явно — печать ≠ взаимодействие.

## Классификация kind из экрана (для fallback и прозаичного вопроса)

Чистая функция в `screen.js` рядом с `extractQuestion`:

```js
function inferWaitingKind(snapshot) {
  const text = String(snapshot || '');
  if (/No, and tell Claude|Do you want\b/i.test(text)) return 'permission';
  if (hasNumberedOptions(text)) return 'question';   // OPTION_RE построчно
  if (/Сейчас от тебя/i.test(text)) return 'question';
  if (extractQuestion(text)) return 'question';
  return null; // не уверены — generic «ждёт», без вранья
}
```

`labelFor`: `permission → 'разрешение'`, `question → 'вопрос'`, `null → 'ждёт ответа'`.

## Установка хуков (opt-in)

Чекбокс в настройках «Точный статус через хуки Claude» (дефолт выкл):
- **Вкл:** мержим в `~/.claude/settings.json` наши маркированные хуки
  (`UserPromptSubmit`, `Stop`, `PermissionRequest`, `PreToolUse:AskUserQuestion`),
  каждый возвращает `{ "terminalSequence": "<OSC c нашим маркером + session_id>" }`.
- **Выкл:** снимаем только свои маркированные записи, чужие хуки не трогаем.
- Никогда не затираем чужое.

Скрипт хука — тонкий (`hooks/swarm-signal.mjs` рядом с app): читает stdin JSON,
по `hook_event_name`/`notification_type`/`tool_name` печатает JSON с OSC-меткой.
