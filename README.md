# Swarm

Swarm держит несколько сессий Claude Code в одном окне. Каждая вкладка — отдельный процесс `claude` в отдельной папке проекта, и вкладка красится по состоянию агента: работает, ждёт ответа, закончил. Это нужно, чтобы вести три-четыре задачи параллельно и не следить за каждой: приложение само покажет и подскажет уведомлением, кто уперся в вопрос. Когда вас нет за компьютером, ответить можно из Telegram, в том числе голосовым.

Своей авторизации у Swarm нет. Он вызывает тот же `claude`, что стоит у вас в терминале, и работает на вашей подписке. Токены приложение не читает и не хранит.

Требования: macOS на Apple Silicon или Windows, установленный Claude Code. Проверка — команда `claude --version` в терминале.

Сборка для macOS подписана ad-hoc, поэтому первый запуск система блокирует. Снять карантин с перетащенного в «Программы» приложения:

```bash
xattr -dr com.apple.quarantine /Applications/Swarm.app
```

После этого приложение открывается как любое другое. Без терминала тоже можно: попробовать открыть Swarm, получить отказ, затем в **Системные настройки → Приватность и безопасность** нажать **Open Anyway** — кнопка появляется там только после неудачной попытки. Обход через правый клик → Open в macOS 15 и новее не работает.

Новые версии Swarm находит сам и ставит по кнопке.

## Вкладки и статусы

```
┌─────────────┬─────────────┬─────────────┐
│ api      🟠 │ web      🟡 │ landing  🟢 │
│ работает    │ разрешение  │ готов       │
│ 1:42        │ 0:08        │             │
└─────────────┴─────────────┴─────────────┘
        ▼ терминал выбранной вкладки
  Bash(npm test) — разрешить?  1) Да  2) Нет
```

| Цвет | Состояние |
|---|---|
| 🟠 | работает: печатает, думает, гоняет инструмент |
| 🟡 | ждёт ответа, и видно, чего именно ждёт: разрешение или вопрос |
| 🟢 | ход закончен |
| ⚪ | сессия закрыта |

Состояние берётся из журнала сессии, который Клод пишет сам (`~/.claude/projects/**.jsonl`), а не угадывается по картинке в терминале. Поэтому вопрос виден дословно и целиком, даже если на экране он уже уехал вверх. Запрос разрешения в журнал не попадает — он живёт только на экране, оттуда и читается.

Когда агент в фоне переходит в «ждёт ответа» или «готов», приходит системное уведомление. Клик по нему открывает нужную вкладку.

## Как работать

- `⌘O` — новая вкладка с выбором папки. Агент стартует в ней и видит код проекта.
- `⌘T` — то же, но в папке по умолчанию (`~/ClaudeSwarm`).
- `⌘1`–`⌘9`, клик по карточке — переключение. `⌘W` — закрыть вкладку вместе с процессом.
- `⌘0` — Пульт: одна вкладка со всеми, кто ждёт ответа, с таймером ожидания. Отвечаете в неё, очередь переходит к следующему.
- `⌘L` — раскладка: рейл слева или плашки-дашборд сверху.
- Внизу окна git-бар: ветка текущей папки, переключение, fetch/pull.

Настройки — галочками в самом приложении, править файлы не нужно.

## Telegram

Мост связывает вкладки с группой в Telegram: тема на вкладку. Список тем в телефоне — это список агентов.

```
Мои агенты
├── api        2   ❓ миграцию катать сразу или ждать?
├── web            ✅ собрал, тесты зелёные
└── landing        ✅ готов
```

В теме нужной вкладки просто пишете текст, он уходит в живую сессию. Ответ агента приходит туда же, целиком. Запрос разрешения приходит кнопками, в сообщении видно команду, которую одобряете. Голосовые распознаются на самой машине и наружу не уходят.

Настройка — три шага в «Настройки → Telegram», каждый с проверкой:

1. `@BotFather` → `/newbot`, полученный токен вставить в первый шаг.
2. Создать группу, включить в ней «Темы», нажать «Привязать группу» и отсканировать QR.
3. Сделать бота администратором.

Бот ваш собственный, сервер не нужен: приложение опрашивает Telegram само, наружу не открывается ни порт, ни адрес. Токен хранится зашифрованным ключом keychain.

| Команда | Что делает |
|---|---|
| `/tabs` | вкладки и их состояние |
| `/usage` | заполнение контекста по вкладкам, окна подписки на 5 часов и неделю со временем сброса |
| `/new` | ещё один агент в папке этой темы |
| `/sync` | привести темы в соответствие с вкладками |
| `/help` | напоминалка по командам |

## Если что-то не так

- **`claude: command not found` во вкладке.** Claude Code не виден login-шеллу. Swarm запускает ровно эту команду, так что сначала проверьте `claude --version` в обычном терминале.
- **Приложение не открывается после установки.** Снимите карантин: `xattr -dr com.apple.quarantine /Applications/Swarm.app`, см. «Скачать».
- **macOS сыплет запросами доступа к файлам.** Запускайте агентов в папках проектов (`⌘O`), а не в домашней.

Подробное руководство по всем настройкам — [`ИНСТРУКЦИЯ.md`](ИНСТРУКЦИЯ.md). Запуск на Windows — [`WINDOWS.md`](WINDOWS.md). История версий — [`CHANGELOG.md`](CHANGELOG.md).

## Разработка

Electron, node-pty, xterm.js. Внешних сервисов нет.

```bash
npm install       # зависимости и node-pty под ABI Electron
npm start
npm test          # чистый Node, без Electron
```

| Файл | Что делает |
|------|-----------|
| `main.js` | Electron main: pty-сессии, детект статуса, IPC |
| `preload.js` | Мост `window.swarm` между рендером и main |
| `git.js` | git-пломбинг для нижнего бара |
| `screen.js` | Разбор снимка экрана: строка вопроса и тип запроса |
| `detector.js` | Машина статусов: экранный детект, замок «ждёт», арбитраж с хуками |
| `osc.js` | Парсер невидимых маркеров хуков из потока pty |
| `hook-config.js`, `hooks/swarm-signal.mjs` | Конфиг и скрипт хуков Claude (opt-in) |
| `transcript.js` | Разбор журнала сессии: чем занят агент и текст вопроса |
| `ask-phrases.js` | Фразы «агент зовёт тебя»: нормализация и матчер |
| `agent-rules.js` | Правило для агента из тех же фраз: строка запуска и блок для `CLAUDE.md` |
| `telegram.js` | Протокол моста: long polling, разбор апдейтов, маршрутизация |
| `voice.js` | Голос в текст: WAV, поиск whisper.cpp, разбор вывода |
| `renderer/` | UI: вкладки, терминалы, раскладки, покраска статусов |
| `scripts/release.mjs` | Скрипт релиза |

Статус собирается из трёх источников по старшинству: хук, журнал сессии, экран. Хуки включаются в «Настройки → Запуск» и только для вкладок, запущенных приложением; глобальный `~/.claude/settings.json` не меняется. Вкладка привязана к своему журналу через `--session-id`, который задаёт само приложение.

Сборка идёт на своей платформе для каждой ОС: `npm run dist` на маке даёт `.dmg` под arm64, `.exe` собирает CI по тегу или `npm run dist:win` на Windows.

Релиз:

```bash
gh auth login                 # один раз, нужны scope repo и workflow
npm run release -- patch      # или minor / major
```

Скрипт гоняет тесты, поднимает версию, дописывает `CHANGELOG.md`, обновляет блок ссылок в этом файле, коммитит с тегом, собирает `.dmg`, пушит и создаёт релиз черновиком с `.dmg`, `app.asar` и `manifest.json`. Пуш тега запускает CI: тот собирает Windows `.exe`, доливает в тот же релиз и снимает черновик. Порядок важен: автообновление ходит за `releases/latest/download/manifest.json`, а черновики в `latest` не попадают, поэтому до сборки `.exe` новой версии для обновлялки не существует.
