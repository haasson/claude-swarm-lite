# Claude Swarm Lite

Мини-пульт для нескольких сессий Claude Code сразу. Каждая вкладка — настоящий
процесс `claude`, запущенный в login-шелле и наследующий твою авторизацию (никаких
токенов приложение не трогает — работает на твоей обычной подписке). Вместо прыганья
по вкладкам терминала видишь дашборд: кто работает, кто ждёт ответа, кто закончил.

Electron + node-pty + xterm.js.

## Запуск (из исходников)

```bash
npm install       # ставит зависимости + подтягивает node-pty под ABI Electron
npm start
```

Нужен установленный и залогиненный Claude Code (`claude --version` работает в терминале).

## Возможности

- Несколько независимых сессий Claude во вкладках (⌘T новая, ⌘W закрыть, ⌘1–9 переключение).
- Две раскладки (⌘L): рейл слева или плашки-дашборд сверху. Выбор запоминается.
- Статус каждого агента по цвету: **работает** / **ждёт ответа** / **готов** / **завершён**.
  Когда агент ждёт — различаем **разрешение** (нажать да/нет) и **вопрос**, и показываем
  это на вкладке, в Пульте и в уведомлении. Статус «ждёт» держится «замком» до
  возобновления работы агента, поэтому не мигает на перерисовках и не теряется, когда
  вопрос уезжает за край экрана.
- **Статус из стенограммы Клода.** Клод пишет каждое сообщение в
  `~/.claude/projects/**.jsonl` по ходу дела, и приложение читает этот файл: открытый
  вызов инструмента — работает, результат — думает, тихое сообщение — конец хода.
  Никакого угадывания по пикселям, и вопрос виден дословно и целиком, даже когда он
  уехал за край экрана. Вкладка привязывается к своему файлу точно: приложение само
  задаёт `--session-id` при запуске. Чего файл не видит — диалог разрешения (он живёт
  только на экране), поэтому экран и хуки остаются.
- **Точный статус через хуки Claude** (опционально, «Настройки → Запуск», по умолчанию
  выкл). Хуки — единственный канал, который видит диалоги: просит разрешение / задал
  структурный вопрос. Включается только для вкладок, запущенных приложением — твой
  глобальный `~/.claude/settings.json` не трогается. Порядок старшинства: хук →
  стенограмма → экран.
- **Фразы, которыми агент зовёт тебя** («Настройки → Запуск»). Клод не сообщает,
  закончил он ход *делом* или *вопросом* — событие одно и то же. Единственный признак —
  как сам агент заканчивает сообщение; по умолчанию это «Сейчас от тебя: …». Свои
  фразы задаются списком, по одной в строке, и работают в обоих режимах: и при чтении
  экрана, и в хуке (там мы смотрим текст последней реплики, а не экран). Продолжение
  вида «ничего, жди…» вопросом не считается.
- **Пульт** (⌘0) — одна вкладка со всеми, кто ждёт ответа: чип на агента с
  типом запроса (разрешение/вопрос) и таймером, под ним живой терминал выбранного.
  Отвечаешь прямо в него, очередь сама переходит к следующему — и такой
  самостоятельный переход объявляет себя: плашка с именем и типом запроса,
  подсветка рамки терминала и импульс на чипе. Когда переключаешься сам
  (чип, вкладка, ⌘1–9), всё как раньше — мгновенно и молча. Отключается в
  «Настройки → Вид».
- Нижний git-бар: ветка активной папки, переключение, fetch/pull (в стиле VS Code).

## Структура

| Файл | Что делает |
|------|-----------|
| `main.js` | Electron main: pty-сессии, детект статуса, IPC |
| `preload.js` | Мост `window.swarm` между рендером и main |
| `git.js` | git-пломбинг для нижнего бара (чистый Node) |
| `screen.js` | Разбор снимка экрана: строка вопроса + тип запроса (чистый Node) |
| `detector.js` | Машина статусов: экранный детект, замок «ждёт», арбитраж с хуками |
| `osc.js` | Парсер невидимых маркеров хуков из потока pty |
| `hook-config.js` / `hooks/swarm-signal.mjs` | Конфиг и скрипт хуков Claude (opt-in) |
| `renderer/` | UI: вкладки, xterm-терминалы, раскладки, покраска статусов |
| `scripts/release.mjs` | Скрипт релиза (см. ниже) |

## Сборка и релиз

Приложение нативное, поэтому каждая ОС собирается на своей платформе:

- **macOS** (`.dmg`) — только на Mac: `npm run dist`. Только Apple Silicon (arm64).
- **Windows** (`.exe`) — на Windows-машине `npm run dist:win`, **или** в GitLab CI
  на Linux-раннере через Wine (node-pty подтягивает готовый win32-бинарь, компилятор
  не нужен). CI собирает `.exe` автоматически при пуше тега.

### Выпуск версии — одной командой

```bash
export GITLAB_TOKEN=<PAT с scope api>
npm run release -- patch      # или minor / major
```

Скрипт: поднимает версию, дописывает `CHANGELOG.md`, обновляет ссылки в этом README,
коммитит и ставит тег `vX.Y.Z`, собирает `.dmg` и заливает его в GitLab-реестр пакетов,
пушит `main` + тег. Пуш тега запускает CI: тот собирает Windows `.exe` и создаёт
**GitLab Release** со ссылками на обе сборки.

> Ссылки на сборки ведут в приватный GitLab и требуют доступа к репозиторию.

Полная история версий — в [`CHANGELOG.md`](CHANGELOG.md).
