# 🐝 Swarm

**Пульт для нескольких агентов Claude Code сразу — на маке и с телефона.**

</div>

Обычно с Клодом работают в одном терминале: одна задача, и вы сидите и смотрите, как он её делает. Swarm превращает это в дашборд: каждая вкладка — свой агент в своей папке проекта, а цвет карточки сразу говорит, кто работает, кто застрял на вопросе и кто уже закончил, так что можно раздать три задачи и заниматься своими делами — приложение само позовёт, когда вы понадобитесь, а если вы отошли от компьютера, продолжите переписку с агентами в Телеграме, включая голосовые. Это не свой ИИ и не подписка: Swarm запускает тот же самый `claude`, что стоит у вас в терминале, на вашей обычной авторизации — токенов он не видит и не хранит.

## Как это выглядит

Три агента в трёх проектах, один ждёт вас:

```
┌─────────────┬─────────────┬─────────────┐
│ api      🟠 │ web      🟡 │ landing  🟢 │
│ работает    │ разрешение  │ готов       │
│ 1:42        │ 0:08        │             │
└─────────────┴─────────────┴─────────────┘
        ▼ терминал выбранного агента
  Bash(npm test) — разрешить?  1) Да  2) Нет
```

| Цвет | Что значит | Что делать |
|---|---|---|
| 🟠 **работает** | печатает, думает, гоняет команды | ничего, он занят |
| 🟡 **ждёт ответа** | задал вопрос или просит разрешение | ответить — видно, что именно спрашивают |
| 🟢 **готов** | ход закончен | дать следующую задачу |
| ⚪ **завершён** | сессия закрыта | закрыть вкладку |

Статус не угадывается по картинке на экране: приложение читает журнал самого Клода, поэтому вопрос виден дословно и целиком, даже если на экране он уже уехал вверх.

## Начать за две минуты

1. **⌘O** — выбрать папку проекта. Агент стартует прямо в ней и видит ваш код.
2. Написать задачу как обычно: *«почини падающий тест в checkout»*. Карточка станет 🟠.
3. **⌘O** ещё раз — второй агент в другом проекте. И третий. Они не мешают друг другу.
4. Первый упёрся в вопрос → уведомление macOS + карточка 🟡 → нажали, ответили.
5. Позеленел 🟢 — следующая задача, или **⌘W** закрыть.

Когда ждут сразу несколько — **⌘0** открывает **Пульт**: одна вкладка со всеми, кто требует ответа, с таймером ожидания. Отвечаете в неё, и очередь сама переходит к следующему.

## Что вы получаете

- **Несколько проектов одновременно.** Каждая вкладка — отдельный агент в отдельной папке, со своей историей.
- **Приложение зовёт вас само.** Системное уведомление, когда агент упёрся в вопрос или закончил. Клик — и вы в нужной вкладке.
- **Видно, чего от вас хотят.** «Разрешение» (нажать да/нет) и «вопрос» различаются на карточке, в Пульте и в уведомлении.
- **Очередь ожидающих** — Пульт (⌘0) вместо беганья по вкладкам.
- **Телеграм с телефона** — переписка с агентами из очереди в магазине, включая голосовые сообщения (см. ниже).
- **Две раскладки** (⌘L): рейл слева или плашки-дашборд сверху — как удобнее.
- **Работа с git** внизу окна: текущая ветка, переключение, fetch/pull — как в VS Code.
- **Расход подписки** одной командой: сколько занято контекста по каждой вкладке и сколько осталось в окнах 5 часов / недели.

Всё включается галочками в «Настройках» — в консоль лезть не нужно ни разу.

## Телеграм: агенты в кармане

Встали из-за компьютера — агенты продолжают работать. Мост связывает их с вашим телефоном: **список тем в группе = список ваших агентов**.

```
Мои агенты
├── api        2   ❓ миграцию катать сразу или ждать?
├── web            ✅ собрал, тесты зелёные
└── landing        ✅ готов
```

Заходите в тему — и просто пишете, как будто набрали текст на клавиатуре. Агент закончил ход — ответ приходит в ту же тему, целиком. Запрос разрешения приходит **кнопками** с командой, которую вы одобряете. Голосовые распознаются на вашей же машине и никуда не отправляются.

**Настройка — три шага в «Настройки → Телеграм»**, мастер ведёт за руку и сам проверяет, что всё сошлось:

1. `@BotFather` → `/newbot` → вставить полученный токен;
2. создать группу, включить в ней «Темы», нажать «Привязать группу» и отсканировать QR;
3. сделать бота администратором — готово.

Бот ваш личный, сервер и VPS не нужны: приложение стучится в Телеграм само, наружу ничего не открывается, а токен лежит зашифрованным в keychain.

| Команда | Что делает |
|---|---|
| `/tabs` | все вкладки и что у них сейчас |
| `/usage` | расход: контекст по вкладкам, окна 5 часов и недели со временем сброса |
| `/new` | ещё один агент в папке этой темы |
| `/sync` | привести темы в порядок, если такт сбился |
| `/help` | короткая напоминалка |

## Если что-то не так

- **`claude: command not found` во вкладке** — Claude Code не виден шеллу. Проверьте `claude --version` в обычном терминале; приложение запускает ровно эту команду.
- **Не открывается после установки** — правый клик по иконке → Open (см. выше).
- **Сыплются запросы доступа к файлам** — запускайте агентов в конкретных папках проектов (⌘O), а не в домашней.

Подробное руководство со всеми настройками — [`ИНСТРУКЦИЯ.md`](ИНСТРУКЦИЯ.md). Запуск на Windows — [`WINDOWS.md`](WINDOWS.md). История версий — [`CHANGELOG.md`](CHANGELOG.md).

<details>
<summary><b>Для разработчиков</b> — запуск из исходников, структура, релиз</summary>

Electron + node-pty + xterm.js, без внешних сервисов. Каждая вкладка — настоящий процесс `claude` в login-шелле.

```bash
npm install       # зависимости + node-pty под ABI Electron
npm start
npm test          # всё чистым Node, без Electron
```

| Файл | Что делает |
|------|-----------|
| `main.js` | Electron main: pty-сессии, детект статуса, IPC |
| `preload.js` | Мост `window.swarm` между рендером и main |
| `git.js` | git-пломбинг для нижнего бара (чистый Node) |
| `screen.js` | Разбор снимка экрана: строка вопроса + тип запроса |
| `detector.js` | Машина статусов: экранный детект, замок «ждёт», арбитраж с хуками |
| `osc.js` | Парсер невидимых маркеров хуков из потока pty |
| `hook-config.js` / `hooks/swarm-signal.mjs` | Конфиг и скрипт хуков Claude (opt-in) |
| `transcript.js` | Разбор стенограммы Клода: что делает агент и текст вопроса |
| `ask-phrases.js` | Фразы «агент зовёт тебя»: нормализация и матчер |
| `agent-rules.js` | Правило для агента из тех же фраз (запуск и блок для `CLAUDE.md`) |
| `telegram.js` | Протокол моста: long polling, разбор апдейтов, маршрутизация |
| `voice.js` | Голос → текст: WAV, поиск whisper.cpp, разбор вывода |
| `renderer/` | UI: вкладки, xterm-терминалы, раскладки, покраска статусов |
| `scripts/release.mjs` | Скрипт релиза |

**Статус агента** собирается из трёх источников по старшинству: хук → стенограмма → экран. Стенограмма (`~/.claude/projects/**.jsonl`) даёт «работает / думает / конец хода» и точный текст вопроса; вкладка привязана к своему файлу через `--session-id`. Диалог разрешения виден только на экране — поэтому экран и хуки остаются.

**Сборка** — каждая ОС на своей платформе: `npm run dist` (`.dmg`, только arm64) на маке, `.exe` — в GitHub Actions при пуше тега либо `npm run dist:win` на Windows.

**Выпуск версии:**

```bash
gh auth login                 # один раз; scope repo и workflow
npm run release -- patch      # или minor / major
```

Скрипт гоняет тесты, поднимает версию, дописывает `CHANGELOG.md`, обновляет ссылки в блоке «Скачать», коммитит и ставит тег, собирает `.dmg`, пушит и создаёт релиз **черновиком** с `.dmg`, `app.asar` и `manifest.json`. CI по тегу доливает Windows `.exe` и снимает черновик — порядок именно такой, потому что автообновление ходит за `releases/latest/download/manifest.json`, а черновики `latest` не видит: пока `.exe` не собран, новой версии для обновлялки не существует.

</details>
