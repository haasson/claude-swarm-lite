# Swarm — разработка

Electron, node-pty, xterm.js. Внешних сервисов нет.

```bash
npm install       # зависимости и node-pty под ABI Electron
npm start
npm test          # чистый Node, без Electron
```

## Модули

| Файл | Что делает |
|------|-----------|
| `main.js` | Electron main: pty-сессии, детект статуса, IPC |
| `preload.js` | Мост `window.swarm` между рендером и main |
| `git.js` | git-пломбинг для нижнего бара |
| `screen.js` | Разбор снимка экрана: строка вопроса и тип запроса |
| `detector.js` | Машина статусов: экранный детект, замок «ждёт», арбитраж с хуками |
| `osc.js` | Парсер невидимых маркеров хуков из потока pty |
| `hook-config.js`, `hooks/swarm-signal.mjs` | Конфиг и скрипт хуков Claude (opt-in) |
| `transcript.js` | Разбор журнала сессии: чем занят агент и текст вопроса |
| `ask-phrases.js` | Фразы «агент зовёт тебя»: нормализация и матчер |
| `agent-rules.js` | Правило для агента из тех же фраз: строка запуска и блок для `CLAUDE.md` |
| `launch-line.js` | Строка запуска вкладки: длинные значения через окружение, `clear` перед командой |
| `telegram.js` | Протокол моста: long polling, разбор апдейтов, маршрутизация |
| `voice.js` | Голос в текст: WAV, поиск whisper.cpp, разбор вывода |
| `swarm-statusline.js` | Строка статуса Клода: отдаёт нам контекст и окна подписки |
| `updater.js`, `updater-core.js` | Автообновление: манифест, докачка, замена бандла |
| `renderer/` | UI: вкладки, терминалы, раскладки, покраска статусов |
| `scripts/release.mjs` | Скрипт релиза |

Логика, которую можно проверить без Electron, живёт в отдельных файлах чистым Node — отсюда и тесты без запуска приложения. Планы и дизайн-документы по крупным изменениям лежат в `docs/superpowers/`.

## Статус агента

Собирается из трёх источников по старшинству: хук, журнал сессии, экран.

- **Хуки** включаются в «Настройки → Запуск» и только для вкладок, запущенных приложением; глобальный `~/.claude/settings.json` не меняется. Это единственный канал, который видит диалоги: просит разрешение, задал структурный вопрос.
- **Журнал сессии** (`~/.claude/projects/**.jsonl`) даёт «работает / думает / конец хода» и точный текст вопроса. Вкладка привязана к своему файлу через `--session-id`, который задаёт само приложение.
- **Экран** остаётся подстраховкой: диалог разрешения виден только там, и там же работает детект для вкладок, где `claude` запущен не приложением.

## Чужие лончеры

Команда запуска вкладки задаётся пользователем, поэтому в ней может оказаться не Клод. Всё клодовское гейтится одним предикатом — `resume.supports(launcherOf(cmd))` (`renderer/resume.js:24`, стем команды: `claude`, `cld`, `claude-*`). Под этим гейтом живут `--settings` со строкой статуса и хуками, `--append-system-prompt`, `--permission-mode`, `--session-id` и построение `--resume` при восстановлении. Причина именно такая: неизвестный флаг Claude Code не проглатывает молча, а отказывается стартовать, так что для чужой команды лучше не добавить ничего.

Эти флаги приложение не запускает напрямую, а **печатает в оболочку вкладки**, поэтому оболочка их отражает — и первым, что человек видит в новой вкладке, оказывается наша служебная строка. Правило-подсказка одно тянет полтысячи символов. Поэтому длинные значения уезжают в **окружение** самой оболочки (`--append-system-prompt "$SWARM_ASK_RULE"`), а перед командой идёт `clear`, который стирает и её саму: `launch-line.js`. Синтаксис подстановки берётся только для оболочек, которые мы знаем наверняка; для незнакомой (`nu`, `xonsh`) значение по-прежнему пишется прямо в строку — нераскрытая `$SWARM_ASK_RULE` уехала бы Клоду как системный промпт, а нераскрытый путь к настройкам и вовсе не дал бы ему стартовать.

Дальше вниз по цепочке чужой лончер теряет и журнал (`transcript.js` смотрит только в `~/.claude/projects/**`), и опознание диалогов (`PERMISSION_RE` в `screen.js` ловит формулировки Клода). Остаётся экранный детект активности по `lastDataAt`. Список того, что от этого ломается для пользователя, — в разделе «Другие агенты, кроме Клода» в `README.md`; если гейт меняется, править надо оба места.

## Сборка

Приложение нативное, поэтому каждая ОС собирается на своей платформе:

- macOS: `npm run dist` даёт `.dmg` под arm64. Подпись ad-hoc.
- Windows: `.exe` собирает CI по тегу либо `npm run dist:win` на Windows-машине.

## Релиз

```bash
gh auth login                 # один раз, нужны scope repo и workflow
npm run release -- patch      # или minor / major
```

Скрипт гоняет тесты, поднимает версию, дописывает `CHANGELOG.md`, обновляет блок ссылок в `README.md`, коммитит с тегом, собирает `.dmg`, пушит и создаёт релиз черновиком с `.dmg`, `app.asar` и `manifest.json`.

Пуш тега запускает CI: тот собирает Windows `.exe`, доливает в тот же релиз и снимает черновик. Порядок важен: автообновление ходит за `releases/latest/download/manifest.json`, а черновики в `latest` не попадают, поэтому до сборки `.exe` новой версии для обновлялки не существует и никто не попадёт в окно, где манифест обещает установщик, которого ещё нет.

Токены в окружении не нужны: релизы публичные, `gh` авторизуется сам.
